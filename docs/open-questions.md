# Open-questions register

This register tracks questions that are not settled yet. Each row gives the current provisional answer and the ADR that records it, if any.

To resolve a question, update its row (answer, status and owner), then add a new ADR or supersede the linked one (see [adr/README.md](adr/README.md)). Rows are never deleted; a resolved question gets status `resolved` and a link to the deciding ADR.

| OQ-30 | How long may one translation hold the conversion lock of the provider `antimony`? | The provider serializes every translation of the process behind one lock, and a translation in progress is not interrupted. libAntimony's translation time grows faster than the source: a generated chain of 500 reactions took about 0.3 s, of 700 reactions (42 KB) about 0.55 s and of 1000 about 0.8 s, so one large source within the size limit keeps every other conversion of the process waiting, possibly past its deadline. | For a step in a module host (isolation mode `process`): the module hosts of other steps each hold a provider and a lock of their own and never wait for it; and a call with a deadline and a cancellation grace holds the lock no longer than those, after which the module host is killed with the translation in it ([specs/process-isolation.md](specs/process-isolation.md#service-providers)). In the runtime's process: the 16 MiB source limit only (`PRAENORA_MODEL_CONVERSION_MAX_SOURCE_SIZE`); the wait for the lock is cancellable, and modules convert in `create` or `initialize` ([specs/model-conversion-service.md](specs/model-conversion-service.md#the-antimony-provider)).
