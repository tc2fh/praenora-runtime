# ADR-0042: Target descriptor intake

- Status: Proposed
- Date: 2026-11-25
- Supersedes: none
- Superseded by: none
- Amends: [ADR-0022](ADR-0022-target-data-intake.md)

## Context

[ADR-0022](ADR-0022-target-data-intake.md) reads an observation CSV by the observation columns of `ode-uq-spec` and left the `ode-uq-spec` target descriptor unread (OQ-15). The descriptor is the document that gives such a CSV its meaning: its dialect, the mapping of its columns, and its variables with unit, role and bounds. A data set that passes the `ode-uq-spec` validator is described by one, and without it the runtime reads the table and nothing about what it holds: a covariate row and a response row look alike, a wrong unit is not noticed, a column the descriptor does not want is read anyway.

ADR-0022 rejected "reading only descriptors" because it deferred the plain CSV case. Reading the descriptor as an addition keeps that case.

The descriptor schema (`schemas/target.schema.json`) declares JSON Schema 2020-12. [ADR-0043](ADR-0043-json-schema-dialects-and-validator.md) lets the runtime read such a schema as it is.

## Decision

- **Optional and explicit.** An `observation-csv` input may name a descriptor with `descriptor: <path>` (relative to the configuration file, like `path`). An input without one reads and fingerprints exactly as before. There is no discovery: no sibling file and no name convention, because it would hide an input from the configuration. `descriptor` is refused on a `json-document` input and together with `columns` (`CONFIG_INVALID`): the descriptor is the one source of the column mapping. The input needs `path`, `descriptor` or both (a schema rule, `SCHEMA_VIOLATION`).
- **The schema as published.** The descriptor is validated against a copy (LF line endings) of `target.schema.json` (`spec/ode-uq/`, embedded under `ode-uq/`, not a Praenora document format and not in the schema registry), as JSON Schema 2020-12. A descriptor must be JSON, as `ode-uq-spec` writes it (its conventions: "JSON uses no comments, duplicate keys, NaN, or infinity"). The content decides: the bytes are parsed as strict JSON whatever the file is called, and YAML or any other text is `UNSUPPORTED`. There is no rule about the file extension, because the spec has none and a name says nothing about what a file holds. `schema_version` must be `0.0.0` (`FORMAT_VERSION_UNSUPPORTED` otherwise). A schema violation is `SCHEMA_VIOLATION` at the first problem, with the count of the others, located in the descriptor.
- **The data file.** With a descriptor the CSV is `data.href`, resolved against the descriptor's directory (an absolute href as written; `..` is allowed). A remote href (a URI scheme of two or more characters, as the spec's validator reads it) cannot be read, because the runtime reads local files, replays offline and hashes the bytes: it is `INPUT_BINDING_INVALID` unless the configuration also gives `path`, which then wins. When both name a local file they must be the same file (`INPUT_BINDING_INVALID`). `data.sha256`, when present, is compared with the CSV's digest, case-insensitively (`TARGET_DATA_INVALID`, located at `/data/sha256`).
- **Dialect and columns.** `dialect.delimiter` and `dialect.quotechar` go to the CSV parser (each one ASCII character, not a line break, and different from each other: a violation is `SCHEMA_VIOLATION` at the key that was set, the quotechar when both are; a character beyond ASCII is `UNSUPPORTED`). A cell equal to `dialect.missing_token` is an absent cell in the `value`, `unit`, `missing`, `censoring`, `lower_limit`, `upper_limit` and `weight` columns, and never in `series_id`, `variable_id`, `time`, `observation_id`, `group_id` or `batch_id`: the spec says only that the descriptor declares a "missing token" (conventions.md, "the descriptor declares delimiter, quote character, missing token, and time/value column names") and that "an empty value with `missing=true` is missing" (conventions.md, "Null, missing, and censored values"), so the token stands for an absent measurement, not for an identifier; a series called `NA` stays a series. The descriptor's `columns` is the complete mapping: a header named like an optional observation column that the descriptor does not list is not read, and one warning names such columns.
- **Rows against variables.** Every row's `variable_id` must be one of the descriptor's variables, and a non-empty `unit` cell must equal the variable's unit (a cell equal to the missing token is skipped), as the spec's validator checks (`TARGET_DATA_INVALID` at the CSV line). `time_unit`, when present, must equal `run.time.unit` (`INPUT_BINDING_INVALID`); when absent the run's unit is used and one warning says so: the runtime does not guess the default of the project.
- **Stricter than the spec's validator, by decision.** Duplicate variable ids and a `lower_bound` above `upper_bound` are refused (`TARGET_DATA_INVALID`, located in the descriptor); a value outside the bounds of its variable is kept and one warning gives the count and the first. The spec's validator is to check the same (its fork's proposal), and then the two agree.
- **`duplicate_policy`.** Absent: no check, as before. The check runs over every row before the roles remove any, so rows of covariate and validation variables are checked too: the data has to be sound whatever reaches the model. `error`: two rows with the same series, variable and time are `TARGET_DATA_INVALID` (at the later row). `require_observation_id`: such rows are allowed when each has its own non-empty `observation_id`. `aggregate_mean` and `aggregate_median` change the data and are `UNSUPPORTED` for now.
- **Roles.** Only rows of variables whose role is `response`, or that have none, reach the model. Rows of `covariate`, `input` and `validation` variables are counted and one warning gives the count and the first; they are no error, because such exports are legitimate. A covariate reaches a module only through a `json-document` input. Outcomes (P13) are marked by our own top-level `x-` key naming the outcome variables, which carry the role `validation` and so stay out of the model; the runtime keeps `x-` keys opaque and reads none. `x-` keys are allowed only where the schema allows them: at the top level and in `data`.
- **Warnings** use the mechanism of ADR-0022 (`InputSource::notes()`): one diagnostic per kind of finding, with the count and the first case, severity warning, code `TARGET_DATA_INVALID`; they never make a configuration invalid. The CSV file is the location of a finding about rows, the descriptor of one about the descriptor.
- **Fingerprint.** `reproducibility.inputs.<name>` keeps `source` and the CSV's `digest` and gains `descriptor: {digest, schema_version}`. The descriptor digest is the SHA-256 of the canonical JSON of the parts that decide what the runtime does with the data: `columns`, `dialect`, `time_unit`, `duplicate_policy` and the variables' `id`, `unit`, `value_type`, `role` and bounds, with the defaults written out (so a default stated and one left out are one thing), the variables sorted by id, a missing role being `response`, and a bound written as a double with -0 as 0 (so `0`, `0.0`, `-0` and `1e0` forms of a number are one value). The unit, the bounds and the time unit are hashed although they only refuse or warn: the owner decided that what the descriptor declares about the data is part of the run, so a changed bound changes the fingerprint without changing the results of a run whose data stays within it. Prose (`id`, `name`, `description`, `data.*`, the variables' `name`) and `x-` keys are not hashed: moving the CSV or rewording a description does not change a run. Two lists in `io/target_descriptor.cpp`, the hashed and the excluded property paths, together name every property of the embedded schema, and a unit test walks the schema and fails for a property in neither list or both, so a field a later version of the spec adds must be classified. An input without a descriptor has the same entry as before.
- **Run record.** `execution.inputs.<name>` (outside the hash) gains `rows_not_delivered_by_role` and `descriptor_id`; `rows_before_start` counts rows delivered by role only. The formats change in place (run-record 0.2, workflow-config 0.1; no new version), as the compatibility policy allows while nothing outside the repository uses them; the new fields are optional, so existing records stay valid.
- **Browser and WebAssembly.** A descriptor binding needs a file system, like the CSV source ([ADR-0025](ADR-0025-webassembly-strategy.md)); a host without one would pass the descriptor's text and the CSV's bytes through the same loader interface when that seam is built.

## Alternatives considered

- **Reading only descriptors.** Defers the simple CSV case the examples need.
- **Discovering the descriptor next to the CSV.** Hides an input from the configuration.
- **A translated draft-07 copy of the descriptor schema.** Needed while the validator knew only draft-07; with [ADR-0043](ADR-0043-json-schema-dialects-and-validator.md) it would only drift from the spec.
- **Hashing the descriptor file's bytes.** Simple, but the fingerprint would then change with `data.href`, prose and `x-` fields, which cannot change a result; ADR-0016 says paths do not change the fingerprint.
- **A roles filter and a second workflow input for covariates.** Needs a workflow definition with a second input, a shared parse and a decision about static rows in a windowed batch (P9); not needed to keep covariates out of the response batch.
- **Warnings for duplicate variable ids.** The descriptor would be ambiguous; an error is the cheaper rule to explain.

## Consequences

- A data set described by a descriptor is read as described: dialect, columns, units, roles and duplicates are checked, and the descriptor is part of the fingerprint.
- Data that passes today's `ode-uq-spec` validator can be refused by the runtime for duplicate variable ids, an inverted bound or an aggregate duplicate policy, until the validator checks the same.
- Memory is unchanged: the file is parsed once, and a descriptor adds a pass over the rows. A dense file (hundreds of thousands of rows) costs about 1.2 KB per row resident; thinning the export is the cheaper fix, a compact row store is a separate change.
- Covariates and time-varying inputs are not routed to modules by this decision (P9 stays open).
- OQ-15: the descriptor part is answered; the message types and capabilities stay open.
