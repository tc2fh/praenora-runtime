# ADR-0008: JSON Schema draft-07 for all Praenora schemas; schemas embedded in the runtime

- Status: Superseded
- Date: 2026-11-10
- Supersedes: none
- Superseded by: [ADR-0043](ADR-0043-json-schema-dialects-and-validator.md)

## Context

The project mandates pboettch/json-schema-validator, which supports draft-07. Documents, message payloads and module parameters must be validated by machine, and the runtime must work without reading schema files from disk. The upstream `ode-uq-spec` documents use JSON Schema 2020-12.

## Decision

- Every Praenora schema (documents, message payloads, module `parameters_schema`) is JSON Schema draft-07.
- Every Praenora JSON document has `kind` and `format_version`; each (kind, major.minor) pair has one schema file `spec/schemas/<kind>.<major>.<minor>.schema.json`. ABI documents carry `pmp_version` instead and use the kind names `pmp-describe`, `pmp-create`, `pmp-initialize`, `pmp-invocation`, `pmp-result`, `pmp-error` and `pmp-envelope`.
- Schemas and catalog entries are embedded in the runtime binary as generated byte arrays plus an index (avoids MSVC string-literal limits) and are also installed to `share/praenora/`.
- Every schema has the `$id` `urn:praenora:schema:<kind>:<major>.<minor>`, the major.minor of the format version it serves (OQ-3). If the validator does not handle URN ids, the build switches to a reserved non-resolvable base (`https://praenora.invalid/schemas/...`) and records the change here.
- The runtime does not validate `ode-uq-spec` artifacts in the MVP; messages refer to them by `href` and `sha256` (OQ-2).

### Builder notes (Proposed)

- Embedded resources are generated per NAME by `praenora_embed_resources(TARGET <t> NAME <name> BASE_DIR <dir> FILES ...)` (`cmake/PraenoraEmbedResources.cmake`): the generated `<name>_resources.cpp` and `.hpp` expose `<name>_find_resource()` and `<name>_list_resources()`. The runtime uses the name `praenora_runtime` (so its lookup function is `praenora_runtime_find_resource`), with resource paths `schemas/<file>` (from `spec/schemas/*.json`) and `catalog/<path>` (from `spec/catalog/**/*.json`); tests embed their own fixtures under another name. The sources are regenerated when a listed file changes, and the `spec/` globs are re-checked at build time. Resource paths may use only `A-Z a-z 0-9 . _ - + @ /`.
- Schema `$id`s carry the major.minor of the format version, the granularity schemas are kept at: `urn:praenora:schema:<kind>:<major>.<minor>` (for example `urn:praenora:schema:workflow-config:0.1`). json-schema-validator 2.4.1 handles URN ids and `#/definitions/...` references in schemas that have one, so the `https://praenora.invalid` fallback is not needed (OQ-3 stays as answered).
- Before compiling, every schema is checked against the draft-07 meta-schema; a `$schema` other than draft-07 is refused with `SCHEMA_VIOLATION`. External `$ref`s may name embedded Praenora schemas by URN or the draft-07 meta-schema (served from the validator's built-in copy); anything else (files, URLs) is refused, so compiling never reads files or the network.
- String formats: the validator's own checks apply to the formats it implements (`date-time`, `date`, `time`, `uri`, `email`, `hostname`, `ipv4`, `ipv6`, `uuid`, `regex`); formats it does not implement (for example `uri-reference`) are accepted as annotations, which draft-07 allows.
- The validator reports a property rejected by `additionalProperties` at the enclosing object. The runtime reports it at the property itself (`/run/tickz`), so diagnostics point at the offending line, and `additionalProperties: false` violations read "property 'tickz' is not allowed".
- The schema registry maps a document's `format_version` to its major.minor and compiles each schema on first use (thread-safe). Every schema file must have exactly the `$id` its file name implies; a missing or different `$id` is a `SCHEMA_VIOLATION`. Kinds match `[a-z][a-z0-9-]*`.
- The 16 document schemas (`spec/schemas/<kind>.0.1.schema.json`) are self-contained: each copies the definitions it uses (SemVer, identifiers, durations, timestamps, ...) into its own `definitions`, with no reference to another schema file. Identifier maps (step ids, port names, input and output names) are expressed as `patternProperties` with `additionalProperties: false` rather than `propertyNames`, so a bad name is reported at the name's own pointer (`/steps/Bad_Step`). The reserved names `inputs` and `outputs` are excluded by a negative lookahead in the name pattern.
- Durations accept a string matching `^(none|0|[0-9]+(\.[0-9]+)?(ns|us|ms|s|m|h))$` or the integer `0` (YAML reads an unquoted `0` as a number); any other number, such as `5`, is invalid.
- Shapes the specification leaves open were fixed as follows. The run record has `fingerprint`, `reproducibility` (`versions`, `workflow`, `catalog` digests by `id@version`, `time`, `seed`, `ticks` (a count, or `null` when the run lasts until its replay inputs are exhausted), the run's `timeouts`, `inputs`, `steps`) and `execution` (`status`, the run's status; `started_at`, `finished_at`, `ticks_completed`, `error`, `platform`, `overrides`, `validation`, `outputs`, `trace`, and `final_status`, the final status snapshot; ADR-0016). The status snapshot mirrors `StatusSnapshot` field by field, with wall-clock values as RFC 3339 strings (`generated_at`, `started_at`, `last_invocation_at`, `last_success_at`, error `at`). Test-vector cases have an optional `name`. The result document may carry `pmp_version` but does not require it (modules return only `outputs` and `diagnostics`). The error document requires a code of at least 1.
- Catalog message-type schemas use `if`/`then`/`else` for conditional rules: an observation row's `null` value needs `missing: true` or a censored row with its applicable limit; a prediction row needs `quantile` if and only if `prediction_kind` is `quantile`. Schema defaults are written on plain properties, never next to a `$ref` (draft-07 ignores siblings of `$ref`).

## Alternatives considered

- **JSON Schema 2020-12.** Matches `ode-uq-spec`, but the mandated validator does not support it.
- **Hand-written validation code.** No dependency, but duplicates the schema language and drifts from the documented schemas.
- **Schemas read from disk at run time.** Simple, but breaks relocatability and offline defaults.
- **A different validator.** Contradicts the project's dependency list.

## Consequences

- The runtime is self-contained: a build with no `share/` directory still validates.
- Schema authors are limited to draft-07 features.
- A mapping from `ode-uq-spec` 2020-12 schemas is future work (OQ-2).
